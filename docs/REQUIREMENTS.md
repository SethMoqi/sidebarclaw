# 需求说明

## 产品定位

这是一个面向本地 `OpenClaw` 的网页工作台和试验插件。

它的核心作用不是替代 `OpenClaw`，而是为本地网页内容提供一条稳定的工作流：

1. 采集当前页面内容
2. 注入到本地 `OpenClaw`
3. 指定 `agent` 执行任务
4. 在当前会话中继续追问
5. 在 `OpenClaw` 不可用时退回本地 longdoc fallback

## 目标用户

- 需要在浏览网页时把内容快速送入本地 `OpenClaw` 的开发者
- 需要针对网页内容指定不同 `agent` 执行任务的使用者
- 需要本地测试插件、侧栏工作流和 gateway 适配的人

## 核心需求

### 1. OpenClaw 连接

系统必须支持连接本地 `OpenClaw`，并允许用户配置：

- `OpenClaw Base URL`
- `Bearer Token`
- `Model`
- `Agent`

### 2. 安全隔离

敏感连接信息必须与输入内容和会话记录分开存储。

必须满足：

- `Base URL` 和 `Bearer Token` 不进入页面注入 payload
- `Base URL` 和 `Bearer Token` 不进入会话历史
- 输入内容、会话记录、索引文件中不能出现上述敏感字段

### 3. 页面注入

系统必须允许从当前网页采集内容，并将其注入到当前会话。

最小采集范围包括：

- 页面标题
- 页面 URL
- 页面正文文本
- 主要标题或 heading
- 捕获时间

### 4. Agent 指定

用户必须可以在注入和提问时指定 `agent`，并由 gateway 转发到本地 `OpenClaw`。

### 5. 多轮会话

系统必须支持：

- 创建新会话
- 恢复已有会话
- 在同一会话中连续提问
- 保留当前活动文档上下文

### 6. 连接验证

插件设置页必须提供连接测试能力，并返回：

- 当前状态
- 错误信息
- 缓解建议

### 7. Fallback

当本地 `OpenClaw` 不可用时，系统应当允许退回本地 longdoc fallback。

fallback 至少需要支持：

- 文本入库
- 分块
- 本地检索
- 证据回答

## 交互需求

### 插件设置页

设置页负责：

- 保存 gateway 地址
- 保存 OpenClaw 连接信息
- 测试连接
- 展示风险缓解提示

设置页不负责：

- 展示聊天历史
- 注入页面
- 日常问答

### 侧栏

侧栏负责：

- 创建会话
- 显示当前会话
- 注入当前页面
- 使用 prompt 模板辅助提问
- 继续多轮问答

侧栏不负责长期保存敏感连接信息。

## 非目标

当前阶段不要求：

- 直接替代 `OpenClaw` 官方前端
- 实现联网网页抓取
- 实现向量检索或 rerank
- 实现复杂任务编排器
- 实现归档中心或知识库管理后台
- 实现完整 WebSocket 协议适配

## 验收标准

满足以下条件即可认为当前版本达到试验目标：

1. 能在 Chromium 中侧载扩展
2. 能在设置页保存 gateway 与 OpenClaw 配置
3. 能在设置页成功执行连接测试并看到状态反馈
4. 能在侧栏创建新会话
5. 能将当前网页内容注入当前会话
6. 能在侧栏中继续提问
7. 能指定 `agent`
8. 敏感字段不出现在会话文件和输入记录中
9. 当 OpenClaw 不可用时，fallback 可返回本地证据结果

## 后续需求候选

后续可以按优先级评估这些扩展：

1. 真实 WebSocket `chat.send/chat.inject` 适配
2. 插件中的会话列表和切换器
3. 插件中的归档入口
4. 向量检索和 rerank
5. 针对真实 OpenClaw 返回结构的专用结果渲染
